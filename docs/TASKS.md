# mdbijou 任务拆分（Task Breakdown）

> 依据 `docs/DESIGN.md` 拆分。原则：**P0 优先、每个任务可独立验收、交付物与依赖明确**。
> 本文件仅做任务规划，不含实现代码；实现需用户确认后逐项进行。

---

## 0. 编号规则

- `T-XXX` 全局编号，按里程碑分组。
- 每个任务含：**目标 / 交付物 / 验收 / 依赖 / 优先级**。
- 优先级沿用设计文档：P0（必须）/ P1（应该）/ P2（可选）。

## 11. 建议执行顺序

1. **M0**（T-001 → T-006）：先拿到「能打开、能显示」的最小闭环，并记录体积/启动基线。
2. **M1**（T-007 → T-015）：核心渲染；其中 **T-004 的 CJK 选型验证**是首要风险点，建议尽早实测。
3. **M2**（T-016 → T-020）：主题，属 P0 需求。
4. **M3 与 M4 可并行**：平台集成与性能优化互不阻塞。
5. **M5**（T-030 → T-033）收尾增强；其中 **T-031 `highlight` 共用引擎**优先落地，作为 M6 编辑器的前置依赖。
6. **M6**（T-034 → T-040）简单编辑器：先做 **T-034 编辑器选型验证**（CJK/撤销），再进入 T-035..T-040 骨架与能力开发；属 P0 需求。
